# Physics-Based Looping Bouncing Ball Simulation

A comparative analysis of physics simulation implementations across multiple AI language models.

## Technical Overview

This repository contains seven independent implementations of a 2D bouncing ball physics simulation, each generated by a different large language model (LLM). The project serves as a benchmark for comparing code generation capabilities, physics accuracy, and implementation approaches across AI systems.

## Physics Model

All simulations implement Newtonian mechanics with the following core equations:

### Motion Update
```
v(t+Δt) = v(t) + a·Δt
x(t+Δt) = x(t) + v(t+Δt)·Δt
```

### Collision Response
```
v_y(new) = -e · v_y(old)
```
Where `e` is the coefficient of restitution (0 ≤ e ≤ 1).

### Parameters
- **Gravity (g)**: 9.8 m/s² (scaled to pixel coordinates)
- **Restitution (e)**: 0.8-0.85 (typical range across implementations)
- **Time step (Δt)**: Frame-based (requestAnimationFrame)
- **Floor boundary**: Dynamic based on canvas height

## Code Analysis

### Common Patterns
1. **Initialization**: Ball position, velocity, and physics constants
2. **Update loop**: Physics calculations per frame
3. **Render loop**: Canvas drawing operations
4. **Collision handling**: Boundary detection and response

### Variations
- **Gravity implementation**: Direct multiplication vs. constant addition
- **Collision response**: Velocity reversal vs. impulse calculation
- **Visual effects**: Simple circles vs. detailed rendering
- **Error handling**: Minimal vs. robust boundary checks
